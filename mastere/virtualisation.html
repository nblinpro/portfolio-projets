Infrastructure Critique Haute Disponibilité

Migration d'une PME vers une infrastructure de virtualisation open-source moderne — cluster Proxmox 3 nœuds HA, segmentation VLAN, stockage distribué Ceph, pare-feu OPNsense et automatisation complète via Ansible et Terraform.

Contexte

Contexte du Projet

Migration d'une PME depuis une infrastructure legacy vers un cluster de virtualisation moderne, sécurisé et hautement disponible.

Problématique PME

Infrastructure legacy reposant sur des serveurs physiques non virtualisés, sans haute disponibilité (SPOF critiques), sans segmentation réseau, avec des déploiements gérés manuellement et un monitoring absent — les incidents étaient détectés trop tardivement.

Objectifs

  • Cluster Proxmox 3 nœuds avec live migration automatique
  • Segmentation réseau par VLANs (Management · DMZ · LAN)
  • Stockage distribué Ceph + ZFS/iSCSI + NFS
  • Pare-feu OPNsense — isolation et filtrage inter-VLANs
  • Automatisation complète : Ansible, Terraform, Cloud-Init
Cluster

Cluster Proxmox 3 Nœuds HA

Trois serveurs bare-metal identiques forment un quorum Proxmox VE. En cas de défaillance d'un nœud, VMs et conteneurs LXC migrent automatiquement sur les nœuds restants via le HA Manager.

Réseau

Segmentation VLANs & OPNsense

Le réseau est segmenté en trois VLANs distincts filtrés par un pare-feu OPNsense, chacun avec ses propres règles de filtrage inter-zones pour limiter la surface d'attaque en cas de compromission.

VLAN 10 — MGT

Administration des hyperviseurs Proxmox, accès SSH restreint aux administrateurs uniquement.

Management

VLAN 20 — DMZ

Services exposés vers Internet — Nginx Load Balancer, reverse proxy, certificats TLS.

DMZ

VLAN 30 — LAN

Services internes — bases de données LXC, monitoring, GitLab Runner, ressources privées.

LAN Interne

Stockage

Stockage Distribué & Redondant

Ceph Distribué

Stockage bloc distribué natif Proxmox — réplication 3 copies entre les nœuds. Lecture/écriture maintenue même en cas de perte d'un nœud, zéro SPOF.

  • Réplication x3 (1 copie/nœud)
  • CRUSH map automatique
  • Pools RBD pour les VMs HA

ZFS + iSCSI

Stockage local haute performance sur pve-01 via ZFS RAIDZ1 — exposé en iSCSI aux autres nœuds pour les workloads à faible latence.

  • ZFS RAIDZ1 — tolérance 1 disque
  • Snapshots automatiques ZFS
  • Compression LZ4 activée

NFS Partagé

Partages NFS pour les ISOs, les backups Proxmox (PBS) et les données persistantes partagées entre les trois nœuds du cluster.

  • ISO store commun au cluster
  • Proxmox Backup Server (PBS)
  • Rétention snapshots J/S/M
Services

Services Déployés

Nginx HA Cluster + Load Balancer

Deux instances Nginx en HA actif/passif via Keepalived (VIP). Le Load Balancer répartit le trafic HTTP/HTTPS entre les backends applicatifs en DMZ.

  • VIP Keepalived — bascule < 3 secondes
  • Terminaison TLS Let's Encrypt
  • Health checks actifs par backend
  • Logs centralisés vers Prometheus

LXC Bases de Données

Conteneurs LXC non-privilégiés en VLAN LAN pour les bases de données — isolation renforcée, overhead minimal comparé aux VMs complètes.

  • LXC unprivileged — surface réduite
  • Backups PBS automatiques nuit
  • VM vs LXC : -40% overhead RAM
  • Migration HA vers pve-02/03

Monitoring — Zabbix + Prometheus/Grafana

Stack monitoring double couche : Zabbix pour la supervision infra (SNMP, agents) et Prometheus + Grafana pour les métriques applicatives et les tableaux de bord.

  • Agents Zabbix sur les 3 nœuds
  • Node Exporter + Alertmanager
  • Dashboards Grafana cluster HA
  • Alertes mail/webhook configurées

OPNsense — Pare-feu & Routage

VM OPNsense déployée en VLAN Management — assure le routage inter-VLANs et applique les politiques de filtrage (allowlist stricte DMZ → LAN).

  • Règles inter-VLANs allowlist
  • IDS/IPS Suricata activé en DMZ
  • VPN WireGuard administration
  • Logs exportés vers Zabbix
Automatisation

Automatisation & IaC

L'infrastructure entière est décrite en code et redéployable en moins d'une heure. Ansible gère la configuration des nœuds, Terraform provisionne les VMs/LXC via l'API Proxmox, Cloud-Init personnalise chaque instance au boot.

Ansible — ansible/site.yml

# Orchestration complète --- - hosts: proxmox_nodes roles: - role: proxmox_base # Dépôts, sysctl, tuning - role: proxmox_cluster # Corosync, quorum - role: ceph_setup # MON, OSD, pools RBD - role: network_vlans # Bridges, /etc/network - hosts: pve-01 roles: - role: zfs_iscsi # RAIDZ1, export iSCSI - role: nfs_server # ISOs, backups PBS - hosts: all roles: - role: monitoring_agents # Zabbix agent, node_exporter - role: gitlab_runner # Runner pve-03

Terraform — terraform/nginx-ha.tf

# Provisioning VM via API Proxmox resource "proxmox_vm_qemu" "nginx_ha" { count = 2 name = "nginx-ha-0${count.index + 1}" target_node = count.index == 0 ? "pve-01" : "pve-02" clone = "ubuntu-24.04-cloudinit" memory = 2048 cores = 2 network { bridge = "vmbr20" # VLAN DMZ tag = 20 } ipconfig0 = "ip=10.20.20.1${count.index + 1}/24,gw=10.20.20.1" ciuser = "admin" sshkeys = file("~/.ssh/id_ed25519.pub") }
Livrables

4 Phases du Projet

Phase 1

Audit & Design de l'Architecture

Analyse de l'existant, identification des SPOF, dimensionnement du cluster, conception du plan d'adressage VLAN, choix de la solution de stockage (Ceph vs stockage partagé), documentation du schéma réseau et de l'architecture cible.

Phase 2

Implémentation & Tests HA

Déploiement du cluster Proxmox, configuration Ceph/ZFS/NFS, mise en place des VLANs et bridges réseau, déploiement des services (OPNsense, Nginx HA, LXC DB, monitoring). Tests de failover HA : coupure nœud, vérification live migration et continuité de service.

Phase 3

Sécurisation de l'Infrastructure

Configuration des règles OPNsense inter-VLANs, activation IDS/IPS Suricata en DMZ, VPN WireGuard pour l'administration distante, durcissement SSH (clés ED25519, fail2ban), audit des permissions LXC unprivileged et tests d'isolation VLAN.

Phase 4

Rapport Final & Documentation

Rédaction du rapport d'architecture complet — schémas réseau, procédures de déploiement, runbooks opérationnels, résultats des tests de failover HA, analyse comparative VM vs LXC, recommandations d'évolution et documentation des playbooks Ansible.
