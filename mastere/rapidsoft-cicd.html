Projet DevSecOps

Sécuriser le cycle de développement

RapidSoft, éditeur de logiciels pour les secteurs bancaire et assurantiel (100 collaborateurs, 50 développeurs), fait face à une hausse du trafic malveillant et à des incidents graves révélés via Bug Bounty.

La GAP Analysis menée par le RSSI a mis en évidence trois failles critiques : un SDLC sans sécurité intégrée, une méconnaissance OWASP côté développeurs et une absence totale d'automatisation.

Le projet répond en deux missions complémentaires : le patch management automatisé des dépendances et la mise en conformité du pipeline CI/CD GitLab.

Mission 1

Patch Management des Dépendances

Une dépendance déclarée dans le package.json en cache souvent des dizaines d'autres, invisibles sans outillage dédié.

Ce que le développeur déclare

// package.json { "dependencies": { "express": "4.16.0" } } → 1 dépendance déclarée → 0 vulnérabilité visible

Ce qui est réellement installé

// package-lock.json (extrait) accepts · array-flatten · body-parser cookie · debug · depd · destroy ee-first · encodeurl · escape-html finalhandler · fresh · http-errors iconv-lite · inherits · methods mime · negotiator · on-finished parseurl · path-to-regexp · qs · ... → 50+ dépendances transitives → 5 vulnérabilités HIGH cachées

0.1.7 → 0.1.12

Politique RSSI : seuil de blocage fixé à CRITICAL. Les vulnérabilités HIGH génèrent une alerte et déclenchent l'ouverture automatique de Merge Requests Renovate. MTTR cible : 14 jours sur HIGH, 48h sur CRITICAL.

Mission 2

Conformité CI/CD avec Plumber

Sécuriser le code ne suffit pas si un développeur peut désactiver les contrôles en commentant un job : Plumber audite la structure même du pipeline avant son exécution.

Commenter le scan

# security_sca_scan: # stage: security # script: # - trivy fs .

→ Toutes les CVE passent en production.

Image obsolète

image: node:10-alpine # CVE non patchées # depuis avril 2021

→ Failles connues exploitables.

Secrets en clair

script: - export API_KEY="sk_live..." - curl -H "Token: abc123"

→ Credentials leakés dans les logs.

Ruleset RSSI — 6 règles de gouvernance

RS-001 HIGH

Pas d'images obsolètes — node:10 non patché depuis avril 2021 : RS-001 détecte toute image en fin de vie.

RS-002 CRITICAL

Scan SCA obligatoire — analyse Trivy systématique des dépendances, aucun pipeline sans SCA.

RS-003 MEDIUM

Versions pinnées — pas de tag :latest, builds reproductibles et traçables.

RS-004 CRITICAL

Pas de secrets en clair — CI/CD Variables masquées obligatoires, blocage immédiat si credential détecté.

RS-005 HIGH

SAST activé — analyse statique du code source, template GitLab natif inclus.

RS-006 LOW

Artifacts archivés 90 jours — traçabilité pour audit ISO 27001, rapport RSSI et SBOM conservés.
